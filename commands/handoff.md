把当前任务的上下文落盘，使这个会话可以被安全 `/clear`。

工作目录下有三个文件，寿命不同，**不要混写**：

## 1. `DECISIONS.md` — 只追加，永不重写

记录寿命等于整个项目的东西。在文件**末尾追加**一节（不存在则创建），标题为 `## <YYYY-MM-DD> <一句话主题>`，内容包含本次会话新产生的：

- 目标与约束的变化
- 做出的决策，**每条都要写理由**
- **被否决的方案，以及否决的原因** ← 这条最容易漏，但最重要。代码里只留下你最后选的那条路，试过并排除的死路不会留下任何痕迹，下一个会话会兴致勃勃地重新提议它。

如果本次会话没有产生新的决策，就不要动这个文件。**绝对不要重写或精简已有内容**——那是在丢历史。

## 2. `TODO.md` — 树状任务账本，只勾选不删除

记录寿命介于两者之间的东西：**待办**。它专门修一个问题——线性对话里旧消息列的 todo 会被新消息淹没，
展开子任务后父层级的兄弟项就再也没人提起。`STATE.md` 每次整个覆盖，没被抄进去的项就丢了；
`TODO.md` 只改标记、不删行，所以不会丢。

做法与 `/todo` 命令相同（格式也在那里）：回顾**整个会话**出现过的待办，合并进文件：
做完的打 `[x]` 加日期，开始的打 `[~]`，新展开的子任务**缩进到被展开的父项下**，放弃的打 `[-]` 写原因。
不删行，不重新编号。

## 3. `STATE.md` — 整个覆盖

记录只活到下次 `/clear` 的东西：

- 当前进度：做到哪一步了
- 下一步：**只写 `TODO.md` 里接下来要做的 1–3 项的编号和一句话**，不要再维护一份独立的 todo 列表。两份清单必然分叉，分叉之后没人知道哪份是真的。
- 未解决的问题 / 卡点
- 关键路径与命令（可直接复制执行的那种）

两条硬约束：

- **明确区分事实与假设。** 已验证的写「已确认」，没验证的写「假设」或「待验证」。上一轮的猜测在新会话里被当成结论继承，是这套流程最危险的失效模式。
- **总长不超过 150 行。** 超了说明有内容属于决策层，挪到 `DECISIONS.md` 去，而不是把 `STATE.md` 撑大。

## 4. 已完成的改动：交给 git，不要复述

用 `git log --oneline` 和 `git diff --stat` 列出改了什么。**不要用散文复述 diff 的内容**——git 已经无损记录了，复述只会得到一份更差、更贵的副本。

## 5. 提交

```
git add DECISIONS.md STATE.md TODO.md
git commit -m "handoff: <一句话概括本次进展>"
```

只提交这三个文件，**不要 `git add -A`**，不要碰实验产物或未完成的改动。不在 git 仓库里就跳过这步并说明。

## 6. 收尾

做完后，用不超过 5 行报告：改了哪些文件、`STATE.md` 多少行、`TODO.md` 未完成几项、commit 是否成功。然后提示用户现在可以 `/clear` 了。
