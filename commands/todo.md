把本会话到目前为止**提出过、展开过、做完过**的所有待办，对账进工作目录的 `TODO.md`。
这条命令解决的是线性对话的固有缺陷：旧消息里列的 todo 会被新消息淹没，展开子任务后父层级的兄弟项就被遗忘。
`TODO.md` 是任务的**唯一真源**，聊天里出现的 todo 只是提议，写进文件才算登记。

## 文件格式

不存在则创建，存在则**原地修改**。格式固定：

```
# TODO — <项目名>

标记：`[ ]` 待做 · `[~]` 进行中 · `[x] (YYYY-MM-DD)` 已完成 · `[-] (原因)` 放弃
规则：子任务缩进在父项下；只改标记，不删行；聊天里列 todo 之前先写这里

- [ ] 1. <父任务>  ← 来源: <STATE 日期 / 会话日期 / 计划文档章节>
  - [x] 1.1 <子任务> (2026-09-22)
  - [~] 1.2 <子任务>
  - [ ] 1.3 <子任务>
- [-] 2. <任务> (放弃：<一句话原因>)
```

## 对账步骤

1. **读**现有 `TODO.md`（如有）。
2. **回顾整个会话**，列出所有出现过的待办：用户要求的、我提议的、做到一半展开的子任务、以及"以后再说"的。
   只看最近几条消息是不够的，这正是要修的问题。
3. **合并**：
   - 已在文件里的：更新标记。做完的打 `[x]` 并写日期；开始做的打 `[~]`。
   - 新出现的：**挂到正确的父项下面**。展开出来的子任务缩进在被展开的那一项下，不要平铺成新的一级。
   - 父项在所有子项完成前保持 `[ ]` 或 `[~]`，不要因为子项做完了就把父项勾掉。
   - 放弃的：打 `[-]` 并写原因。**不删行**——被删的项下一个会话会重新提出来。
4. **每条一行**，动词开头，写到能直接开工的粒度；模糊的项写清"要回答什么问题"。
5. 编号只在新增时分配，不要因为插入而给已有项重新编号（外部文档可能引用编号）。

## 收尾

用不超过 5 行报告：新增几项、勾掉几项、当前未完成几项，然后**把未完成项按树状列一遍**，这就是本轮之后聊天里唯一应该出现的 todo 视图。
